# Korea_Reconstruction

수도권(서울·경기·인천) **아파트 재건축 사업 진행 현황** 데이터. 정부·지자체가 공개한 자료만 모아 사업장 단위로 합치고, GitHub Actions가 매일 바뀐 부분만 갱신한다.

## 검색 페이지

**https://kyoungwhankim.github.io/Korea_Reconstruction/** — 단지명·별칭, 시도·시군구, 주소, 진행 단계, 용적률·건폐율·세대수·구역면적·준공연도 등 필드별 조건으로 검색. 검색 조건은 주소(URL)에 남아 그대로 공유할 수 있다. 페이지는 `docs/`에 있고 `docs/data/projects.json`을 읽는다(매일 갱신 때 함께 커밋).

## 사업장 등재 기준

사업장은 두 경로로만 올라온다. 둘 다 공공·공개 자료가 근거다.

1. **공공 출처 등재** — 아래 '출처' 표의 서울·경기·인천·국토부 자료와 정비사업 정보몽땅에 행이 있는 사업장. 자동으로 수집·연결된다.
2. **수동 등록(근거 필수)** — 공공 자료에 아직 없는 초기 단계(안전진단, 추진위 준비·동의서 징구) 단지. 서울은 정보몽땅이 안전진단 단계부터 올리지만 경기·인천은 정비(예정)구역 지정 이후만 공공 데이터에 있어, 그 전 단계는 이 경로로만 올라온다. 사람이 기사·고시 링크와 함께 `manual_projects.csv`에 적으면 다음 갱신 때 노후 단지 자료(부동산원 단지 식별정보·K-apt·건축물대장)로 사업장이 만들어진다(아래 '수동 등록' 절). 근거 링크가 없는 행은 무시된다.

수동 등록된 사업장은 `stage_source`=`수동(근거)`, 출처 열에 `manual_projects.csv`로 표시되고, 나중에 공공 출처에 같은 사업장이 실리면 이름·대표 지번으로 같은 `project_id`에 붙는다(출처별 단계 중 가장 진전된 단계가 현재 단계).

## 30년 이상 노후 단지 (`complexes.py`)

재건축 사업장과 별도로, 수도권에서 준공 30년이 넘은 아파트 단지 전체(사업이 아직 없는 단지 포함)를 모은다. 페이지의 **30년 이상 노후 단지** 보기, `output/old_apartments_latest.csv`, `docs/data/apartments.json`.

- **단지의 기준은 한국부동산원 「공동주택 단지 식별정보」**(`identity.py`, 공시대상 공동주택 전수, 수도권 아파트 약 2만 단지): 단지 1개 = `COMPLEX_PK`. 이름 3개(1순위는 국토부 실거래 단지명과 같은 체계)와 옛 이름, PNU(지번), 세대·동수, 사용승인일, 그리고 필요한 단지의 **동 목록·층수**를 받는다(`state/complexes/reb.jsonl`, `reb_dongs.jsonl`; 전수는 분기, 동 목록은 하루 1,500단지씩).
  - 한 지번에 단지가 여럿일 수 있다(예: 산본동 1155-7에 '가야3주공'과 '가야주공(임대)'). 지번은 단지들의 묶음으로만 쓰고, 대지면적·용적률처럼 지번 단위인 값은 "지번 전체 값"으로 표시한다.
  - 부동산원 주소는 '경기도 수원권선구 권선동'처럼 형식이 제각각이고 인천은 개편 전 구 이름을 써서, 지역은 주소가 아니라 PNU의 법정동코드로 정하고 옛 코드는 현재 코드로 바꾼다(`bjd_canonical`).
- **실거래가**를 수도권 83개 시군구 전체에서 받아, 1996년(=올해−30) 이전 준공 단지의 거래를 남긴다 → 준공연도·전용면적별 가격. 거래는 지번 → 단지명 → **동 번호**(aptDong, 약 80% 채워짐) 순으로 단지에 붙이고, 못 가리면 "지번 공통"으로 둔다. 매매는 2006년부터의 이력, 전월세는 최근 12개월(아래 '거래 정보' 절).
- **건축물대장 총괄표제부**를 법정동(동·리 약 2,900곳)마다 나열 → 대지면적·용적률·건폐율·사용승인일(지번 단위). 분기마다 한 바퀴, 매일 100곳씩(`state/complexes/registry.jsonl`, `registry_dongs.json`). 총괄표제부 세대수는 두 배로 적힌 사례가 있어 세대수는 부동산원·K-apt 값을 우선한다.
- 사용승인일이 어디에도 없는 100세대 이상 단지는 동별 표제부로 채운다(매일 150곳).
- 이름: 'N단지'·'N차'가 든 이름을 우선 보여주고(주공6단지세종아파트), 주공 단지는 동 번호의 백 자리로 단지 번호를 추정해 별칭을 더한다(501~516동 → '가야주공5단지', 별칭 종류 `동번호 추정`). 모든 출처의 이름이 별칭이 되어 어느 이름으로든 검색된다.
- 재건축 사업장 대표 지번과 같은 지번의 단지에는 사업 단계를 붙인다. 수동 등록(`manual_projects.csv`)한 사업장은 그 단지(`complex_id`)에만 붙이고, 지번이 같은 다른 단지에는 붙이지 않는다.
- **K-apt**(공동주택관리정보시스템, `AptListService4` 단지 목록·`AptBasisInfoServiceV5` 기본정보): 분기마다 단지 목록, 단지별 기본정보는 한 번 받아 캐시(`state/complexes/kapt*.jsonl`) → 공식 단지명·사용승인일·세대수·동수·최고층·난방·시공사. 의무관리대상(대략 150세대 이상) 단지만 있다. 인증키가 K-apt에 등록되지 않았으면 건너뛴다.
- 준공연도는 부동산원 사용승인일 > K-apt > 실거래 건축년도 > 건축물대장 순으로 쓴다(1960년 이전 값은 오기로 보고 버림).
- 한계: 부동산원에 없는 지번(소규모 단지 등)은 지번 단위 항목으로 남는다(약 100곳). 한 단지가 여러 지번에 걸치면 지번별로 나뉠 수 있다.

현재 단계는 출처들 중 가장 진전된 단계를 쓴다. 출처별 값은 `stage_by_source` 열에, 그 단계를 알려준 출처는 `stage_source`(정보몽땅이면 `stage_evidence`에 사업장 페이지 링크)에 있다. 사람이 뉴스·고시로 확인해 `manual_stage.csv`에 적은 단계가 출처보다 앞서면 `stage_source`=`수동(근거)`, `stage_evidence`=근거 링크다(아래 3단계 절).

단계 체계(14단계): 예정구역·후보지 → 안전진단 → 정비계획수립 → 정비구역지정 → 추진위구성 → 조합설립인가 → 건축심의 → 사업시행인가 → 관리처분인가 → 이주·철거 → 착공 → 분양 → 준공 → 이전고시·청산. 출처의 표현은 `collect_reconstruction.STAGE_ALIASES`로 이 체계에 맞춘다.

### 오픈API 보강 (`enrich.py`, 인증키 필요)

사업장 주소를 법정동코드·지번으로 바꿔(국토교통부 법정동코드 파일) 아래 API로 조회한다. 결과는 `state/` 아래 파일에 따로 저장하고 내보낼 때만 사업장·단지에 붙인다(`tradebook.py`).

| API | 쓰는 값 | 갱신 |
|---|---|---|
| 국토교통부 건축HUB 건축물대장정보 (총괄표제부·표제부) | 대지면적·세대수 → 평균 대지지분(`land_share_m2`), 기존 용적률·건폐율(`bld_far`, `bld_bcr`), 사용승인일 | 지번이 새로 생기거나 바뀐 사업장만 |
| 국토교통부 아파트 매매 실거래가 — 최근 12개월 (`state/trades.jsonl`) | 해제 제외 거래를 지번·단지명으로 사업장에, 지번·단지명·동 번호로 단지에 연결 → 전용면적별 건수·중위·최저·최고·최근가, 전용 평당가 | 매일 최근 3개월만 다시 받음(신고 기한 30일), 수도권 83개 시군구 |

- 오래된 건축물대장은 대지면적이 비어 있는 경우가 많아 대지지분은 일부 사업장만 나온다.
- 준공된 사업장의 지번에는 새 아파트가 있어 `trade_basis = 준공 후 신축`으로 구분한다. 진행 중인 사업장에서 기존 단지보다 훨씬 늦게 지어진 건물의 거래는 뺀다.
- 입주권·분양권은 신축 단지명(예: 올림픽파크포레온)과 신축 지번으로 신고돼 기존 사업장과 자동으로 맞지 않는 경우가 많다. `manual_new_names.csv`(`project_id,new_name`)에 신축 단지명을 적으면 그 이름으로 연결된다(수기 입력, 현재 둔촌주공·신반포4지구). 재개발 사업장의 입주권은 이 저장소 범위 밖이라 버린다.
- 인증키: GitHub Actions는 secret `DATA_GO_KR_KEY`(Decoding 키), 로컬은 `.env`(커밋 안 됨)에 `DATA_GO_KR_KEY=...`. 키가 없으면 보강만 건너뛴다. 요청은 초당 5건으로 제한한다(넘으면 429). 실거래 세 API는 각각 일 10,000건이며 한도 초과 응답(`returnReasonCode 22`)을 받으면 그 서비스는 그날 더 부르지 않는다.
- 실행 순서와 시간: 출처 갱신 → 건축물대장·매매 창·전월세·분양권(약 600건, 2분) → 식별정보·건축물대장 목록·K-apt(각 일 예산) → **매매 이력은 맨 마지막에 실행 시작 32분까지**만 받아, 워크플로 timeout 50분 안에 내보내기·커밋이 끝난다. 하루 두 번 실행해도 이력 호출은 상태 파일의 날짜별 합계로 8,000건을 넘지 않는다.
- 페이지 데이터(`docs/data/apartments.json`, `projects.json`)에는 숫자 요약(12개월 중위·전세가율·이력 건수 등)만 넣고, 건별 목록과 면적대별 표는 `docs/data/trades/<id>.json`에 단지별로 둔다(한 거래가 한 줄이라 diff에 새 거래만 보인다).

## 3단계: 뉴스·고시 감시와 검토 대기열 (`news.py`)

출처 데이터는 월·분기 단위라 단계 변화가 늦게 반영된다(경기도는 1년 가까이). 그래서 매일 뉴스와 고시의 **제목**을 사업장 이름으로 찾아, **현재 단계보다 앞선 단계가 보이면 "검토 대기" 후보**로 올린다. **단계를 자동으로 바꾸지는 않는다** — 사람이 기사를 확인하고 `manual_stage.csv`에 적은 것만 반영된다(재개발닷컴의 '수정 요청'과 같은 사람 확인 단계).

| 출처 | 방법 | 한도·간격 |
|---|---|---|
| 네이버 뉴스 검색 (NAVER API HUB) | 사업장당 질의 1~2건(대표 이름 + 괄호 안 단지명·통칭), 최신순 100건 | 하루 2,000건 이내(무료 한도 25,000건). GitHub secret `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET`, 로컬은 `.env`. 없으면 네이버만 건너뜀 |
| Google News RSS | 사업장당 1건(처음 60일, 그 뒤는 14일 범위) | 키 없음. 요청 간격 0.6초, 요청 제한(429)이면 그날은 중단 |
| 정비사업 정보몽땅 고시/공고 (cleanup.seoul.go.kr 알림마당) | 서울시·자치구가 등록한 정비사업 고시·공고 목록을 하루 한 번 최근 기간만 읽어 서울 사업장 이름과 대조(등록기관이 지역 이름 구실) | 공개 페이지, 초당 1건 이하. 지자체가 여기에 등록한 것만 있고 서울시보·구보 PDF에만 실린 고시는 없다 |

- 대상: 활성 아파트 재건축 사업장 중 마지막 단계(이전고시·청산)가 아닌 곳(약 570곳). 오늘 이미 조회한 사업장은 다시 조회하지 않으므로 14:30 보조 실행은 아침에 못 본 곳만 본다(네이버 예산은 하루 기준).
- **신규 사업장 후보**: 사업장이 없는 노후 단지(`docs/data/apartments.json`에서 `project_id`가 없는 300세대 이상 단지, 약 1,300곳)도 사업장 조회가 끝난 뒤 하루 200곳씩 오래 안 본 순으로 돌아가며 조회한다(약 일주일에 한 바퀴 — 구글 검색 창 14일 안). 질의는 시군구 이름을 앞에 붙인 1건(`군포 가야주공 재건축`). 단지 이름은 흔해서(현대·주공…) 사업장보다 엄격하게 대조한다: 5자 이상의 고유한 이름만 이름만으로 믿고 나머지는 제목에 동·시군구 이름이 함께 있어야 하며, 번호가 있는 이름의 줄기(`상계주공9`의 `상계주공`)는 쓰지 않고(제목의 `상계주공7단지`가 9단지에 붙지 않게), 흔한 이름뿐인 단지(`대림`·`현대`)는 동 이름이 제목에 있어야 한다. 어떤 단계 표현이든(안전진단 통과·추진위 승인·동의서·정비구역 지정 등) 보이면 `kind`=`신규 사업장 후보`로 같은 대기열에 오른다(상태 키 `cx:<complex_id>`). 저장된 후보도 매 실행 때 이 규칙으로 다시 대조한다. 정보몽땅 고시·공고도 사업장 없는 서울 단지와 대조한다. 첫 실행(2026-10-19, 200곳)에서 남산대림(정비계획 주민공람)·창동주공19단지(추진위 승인)·상계주공7단지(추진위 승인)가 올라왔다.
- 판정은 **제목만** 본다. ① 제목에 사업장 별칭이 있어야 한다 — 흔한 이름(현대·주공N단지 등)이나 여러 사업장이 같이 쓰는 별칭, 동·시군구와 같은 이름은 지역 이름이 함께 있어야 하고, '은마'처럼 짧은 고유 이름은 재건축·아파트 같은 말이 함께 있어야 한다. ② 단계 표현을 14단계 체계로 바꾼다(`news.STAGE_PATTERNS`: 안전진단 통과, 정비계획 수립·신속통합기획 확정, 정비구역 지정, 추진위 승인, 조합설립인가·사업시행자 지정, 건축심의·통합심의 통과, 사업시행인가, 관리처분인가, 이주 개시·철거, 착공, 일반분양·청약, 준공·입주, 이전고시·해산). 무산·반려·보류가 있으면 버리고, '앞두고·신청·총회·목표' 같은 말이 있으면 **예정**(아직 아님), 아니면 **확정**으로 표시한다. 시세·분양권 기사는 단계를 언급만 한 것으로 보지 않는다. ③ 기사 단계가 현재 단계보다 앞설 때만 후보다.
- 결과: `output/review_queue_latest.csv`, `docs/data/review.json` → 페이지의 **검토 대기** 탭(종류 · 사업장/단지 · 현재 단계→기사 단계 · 판정 · 기사 링크 · 날짜)과 사업장 상세의 "검토 대기 N건", 목록의 `검토 N` 표시(노후 단지 보기에서는 `후보 N`과 상세의 "신규 사업장 후보"). 상태는 `state/news.jsonl`(사업장별 마지막 조회일 · 본 기사 해시 · 후보)에 두어 매일 새 기사만 본다. 실행 요약(조회 수 · 새 후보)은 Actions 요약에 남는다.
- 후보는 현재 단계가 따라오면(출처 갱신 또는 수동 반영) 자연히 빠지고, 기사 날짜로 90일이 지나도 빠진다. 신규 사업장 후보는 그 단지가 사업장에 연결되면(수동 등록 등) 빠진다. 아닌 것은 `review_dismissed.csv`(`article_id,project_id,note` — 신규 사업장 후보는 두 번째 칸이 `cx:<complex_id>`)에 적으면 빠진다 — 페이지의 **기각 행** 버튼이 그 줄을 복사해 준다. 수동 반영·기각 뒤 `python news.py --rebuild`로 대기열 파일만 다시 만들 수 있다.

### 수동 반영 (`manual_stage.csv`)

| 열 | 내용 |
|---|---|
| `project_id` | 사업장 ID(대기열 · CSV · 페이지 상세의 값) |
| `stage` | 14단계 이름(출처 표현도 `STAGE_ALIASES`로 맞춰 읽는다: 예 `관리처분계획인가`) |
| `date` | 그 단계에 이른 날짜(기사·고시 일자). 비어 있어도 된다 |
| `evidence_url` | 근거 링크(기사·고시). 페이지의 "현재 단계 근거"에 표시된다 |
| `note` | 메모 |

페이지의 **반영 행** 버튼이 이 형식의 한 줄을 복사해 준다(GitHub에서 파일을 열어 붙여 넣고 커밋). 다음 `update_daily.py` 실행 때 — 파일이 바뀌면 모든 사업장을 다시 계산한다 — 수동 단계가 출처 단계보다 앞서면 현재 단계가 되고, `stage_source`=`수동(근거)`, `stage_evidence`=링크, 단계별 일자 열(예: `mgmt_approved_at`)이 채워지며, 변경 이력(`output/changes/`)의 출처 칸에 `manual_stage.csv`로 남는다. 출처가 나중에 같은 단계 이상에 이르면 출처 값이 쓰이므로 수동 행은 자연히 무의미해진다(지우지 않아도 된다). 같은 사업장에 여러 행이 있으면 가장 진전된 단계를 쓴다.

### 수동 등록 (`manual_projects.csv`) — 공공 자료에 아직 없는 사업장

| 열 | 내용 |
|---|---|
| `complex_id` | 단지 ID: 한국부동산원 `COMPLEX_PK`(노후 단지 보기·`old_apartments_latest.csv`의 `complex_id`, 예 `41410100007535`). 부동산원에 없는 지번 단위 항목이면 그 `complex_id`(`lot:법정동코드-산-본번-부번`) |
| `name` | 사업장 이름(페이지에 보일 이름, 예 `가야주공5단지1차`). 비우면 노후 단지 목록의 단지 이름을 쓴다. 단지의 다른 이름(부동산원·K-apt·건축물대장·동번호 추정)은 별칭으로 붙는다 |
| `stage` | 14단계 이름(`STAGE_ALIASES`로 맞춰 읽는다: 예 `안전진단통과`, `추진위승인`) |
| `date` | 그 단계에 이른 날짜(기사·고시 일자). 비어 있어도 된다 |
| `evidence_url` | 근거 링크(기사·고시). **필수** — 없으면 그 행은 무시된다. 페이지의 "현재 단계 근거"에 표시된다 |
| `note` | 메모 |

처리 방식: 이 파일은 보통 출처와 같은 자리에 있다(출처 이름 `manual_projects.csv`, `state/source_rows/manual_projects.jsonl`, probe = 파일 해시). 파일이 바뀐 날에만 다시 읽어 행 단위로 비교하고, 새 행은 노후 단지 자료에서 이름·별칭·주소·대표 지번·세대수·동수·준공연도를 가져와 다른 출처 행과 같은 모양으로 둔 뒤 `link_row`로 기존 사업장에 붙이거나 새 사업장을 만든다(`project_id`는 `경기-군포-가야주공51`처럼 기존 규칙, 변경 이력은 `신규 사업장(수동 등록)`). 행을 지우면 그 사업장은 '출처에서 사라짐'으로 남는다.

- `stage_source`=`수동(근거)`, `stage_evidence`=링크, `stage_by_source`에 `수동등록=안전진단`, `sources`에 `manual_projects.csv`.
- 노후 단지 보기의 해당 단지에도 `project_id`·단계가 붙는다(지번이 같은 다른 단지에는 붙지 않는다).
- 나중에 공공 출처에 같은 사업장이 실리면: 이름 유사도 0.75 이상이거나, **대표 지번이 같은 기존 사업장이 하나뿐이고 이름이 0.5 이상 닮으면**(`가야주공5단지1차` ↔ `가야5단지1차`·`산본 가야5단지`) 같은 `project_id`에 붙고, 현재 단계는 출처별 단계 중 가장 진전된 것이 된다.
- 검토 대기의 **신규 사업장 후보** 행에서 **등록 행** 버튼이 이 형식의 한 줄(`complex_id,단지 이름,기사 단계,기사 날짜,링크,`)을 복사해 준다. 단계·날짜·이름은 기사를 확인하고 고쳐서 넣는다.
- 첫 등록: 군포 산본 **가야주공5단지1차**(부동산원 PK 41410100007535, 산본동 1155, 501~516동 1,601세대) — 안전진단, 2026-04-08, [뉴시스 기사](https://www.newsis.com/view/NISX20260408_0003581916). 경기도·국토부 자료에는 아직 없다.

## 매일 갱신 (`.github/workflows/daily-update.yml`)

매일 07:30 KST에 `update_daily.py`가 실행되고, 이어서 `news.py`가 뉴스·고시를 확인해 검토 대기열을 갱신한다. 바뀐 것이 있을 때만 커밋한다.

1. **출처 단위**: 파일 ID·파일명(probe)이 그대로면 내려받지 않는다. probe가 없는 출처는 받아서 내용 해시를 비교한다.
2. **행 단위**: 바뀐 출처만 이전 행과 비교해 추가·수정·삭제된 행을 고른다.
3. **사업장 단위**: 그 행에 연결된 사업장만 다시 계산하고 필드별 변경 이력을 남긴다.

상태(`state/`)는 정렬된 JSONL 텍스트라 커밋 diff에 바뀐 행만 보인다. 일부 출처가 실패하면 성공한 부분은 커밋하고 그 출처는 이전 데이터를 유지한다. 하루 이틀의 일시 장애(GitHub 실행기의 해외 IP를 막는 부천시·경기데이터드림 등)는 요약에 ⚠️로만 남기고, 같은 출처가 3일을 넘겨 계속 실패하면 실행을 실패(❌)로 표시한다(`state/meta.json`의 `fail_since:*`).

**부분 응답은 반영하지 않는다.** 출처가 목록의 일부만 돌려주면(해외 IP 차단, 빈 쪽 응답 등) 행이 대량으로 "삭제"된 것처럼 보이는데, 지운 행을 되살리는 비용이 훨씬 크므로 두 겹으로 막는다.
- 정보몽땅 목록은 1쪽에서 읽은 쪽 수·전체 건수와 맞지 않으면(짧은 쪽, 빈 쪽, 같은 쪽 반복) 쪽을 다시 받고, 끝내 안 맞으면 그 회차를 버린다.
- 어느 출처든 살아 있는 행의 30%가 넘게 한꺼번에 사라지는 응답은 부분 응답으로 보고 실패 처리한다(기존 행 유지, 실행은 실패 표시). 실제로 줄어든 것이면 `python update_daily.py --accept-shrink`로 한 번 반영한다.
Actions 탭 → *Daily reconstruction update* → *Run workflow*로 수동 실행할 수 있다(`force`: 모든 출처를 강제로 비교).

```bash
python search_reconstruction.py 은마          # 어떤 이름으로든 검색 (--all: 단계별 일자)
python update_daily.py --dry-run              # 지금 갱신하면 무엇이 바뀌는지만 확인
python collect_reconstruction.py              # (검증용) 상태와 무관하게 전체를 새로 구축 → output/*_full_*.csv
python update_daily.py --migrate              # 수집 열을 늘린 뒤 1회: 새 열 때문에 생긴 변경은 이력에서 제외
python -m http.server 8000 --directory docs   # 검색 페이지 로컬 확인 → http://localhost:8000
python update_daily.py --skip-enrich          # 오픈API 보강 없이 출처만 갱신
python update_daily.py --history-budget 500   # 이번 실행의 매매 이력(2006년~) 요청 수를 제한(0이면 받지 않음)
python news.py --dry-run --only 은마           # 뉴스·고시 감시를 특정 사업장·단지만 시험(저장 안 함)
python news.py --complex-limit 0              # 사업장 없는 노후 단지(신규 사업장 후보) 조회는 건너뜀
python news.py --rebuild                      # manual_stage.csv·review_dismissed.csv 반영 뒤 대기열 파일만 다시 생성
```

`manual_aliases.csv`에 행을 추가하면 자동으로 못 묶은 같은 사업장을 합치거나, 공식 자료에 없는 통칭(예: `압구정 현대`)을 별칭으로 붙일 수 있다. `manual_stage.csv`에 행을 추가하면 사람이 확인한 단계가 근거 링크와 함께 반영된다. `manual_projects.csv`에 행을 추가하면 공공 자료에 없는 단지가 근거 링크와 함께 사업장으로 올라온다. 모두 다음 실행 때 반영된다.

## 한계

- 경기 광주·양주·여주·포천·가평·양평·연천, 인천 영종·검단·옹진은 공개 데이터셋이 없다.
- 소규모재건축·리모델링은 포함하지 않는다. 안전진단 단계는 서울(정보몽땅)만 자동으로 잡히고, 경기·인천은 정비구역 지정 전 단계가 공공 데이터에 없다 — 이런 단지는 뉴스 감시의 신규 사업장 후보를 사람이 확인해 `manual_projects.csv`로 등록해야 올라온다.
- 경기도 도 데이터는 기준일이 1년 가까이 지연된 상태다(2025-09-30). 뉴스·고시 감시(3단계)가 후보를 올리면 사람이 확인해 `manual_stage.csv`로 보완한다.
- 경기데이터드림(data.gg.go.kr)과 부천시(www.bucheon.go.kr)는 GitHub 실행기(해외 IP)에서 간헐적으로 접속 자체가 막힌다(TCP connect timeout — 2026-10-18 실행 #7·#8은 두 출처가 모두 실패, 같은 날 #6·#9와 다음 날 정기 실행은 성공). 그날은 ⚠️로 남기고 이전 데이터를 유지하며, 14:30 KST 보조 실행이 다시 시도한다. 접속 단계에서 끊기므로 User-Agent·Accept-Language 같은 요청 헤더로는 달라지지 않고, 프록시·우회 서버는 쓰지 않는다.
- 두 출처의 공공 대체 경로는 없다(2026-10-19 확인). 공공데이터포털의 「경기도_일반 정비 사업 추진 현황」(15119846)과 「경기도_부천시_도시정비사업추진현황」(15051011)은 파일 없이 원 사이트 URL만 등록된 항목이고(제공형태 "기관자체에서 다운로드"), 둘 다 오픈API 변환(api.odcloud.kr)이 없으며("등록되지 않은 서비스"), 경기데이터드림 Open API에도 이 데이터셋은 없다. 시군이 따로 올린 파일(고양 15085975, 안양 15150142, 이천 15150059, 하남 API 15150356)은 일부 시군뿐이고 열 구성도 달라 대체가 못 된다.
- 뉴스 감시는 기사 제목만 보므로 오탐·누락이 있고, 고시는 정보몽땅 고시/공고(서울시·자치구 등록분)만 본다(경기·인천 고시는 아직 없다).
- 출처가 대부분 월·분기 단위로 갱신되므로 매일 실행해도 변경이 없는 날이 많다.
- `manual_aliases.csv`의 압구정 통칭 행과 `manual_new_names.csv`의 신축 단지명, `manual_projects.csv`의 수동 등록 사업장은 공식 자료가 아닌 수기 입력이다(수동 등록은 근거 링크가 있는 것만).
- 매매 이력은 처음 약 3일에 걸쳐 채워지고(최신 달부터), 해가 바뀌어 노후 기준이 올라가면 다시 한 바퀴 받는다. 받을 때 거른 거래(노후 기준보다 늦게 지어진 단지)는 그때까지 이력에 없다. 거래 건축년도가 비어 있고 부동산원·건축물대장에도 없는 지번의 거래는 사업장에 연결된 경우에만 남는다.
- 전세가율은 같은 전용면적대(㎡ 반올림)의 12개월 중위끼리 비교한 값이라 거래가 적은 면적대에서는 흔들릴 수 있다.
